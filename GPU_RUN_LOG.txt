Changed (new files, none yet run on GPU):
- `isaacpjt/two_bone_ik.py`: standalone two-bone IK solver (shoulder+elbow
  angles from a 3D target, analytic law-of-cosines + pole-vector bend
  plane). Unit-verified with an in-memory USD stage matching the real
  Shoulder->Elbow->hand hierarchy: 20 random reachable targets all landed
  to ~1e-16 error. The one non-obvious subtlety, worth knowing before
  touching this again: the elbow's `xformOp:orient` is a LOCAL rotation,
  so the world-space target direction must be transformed by the shoulder
  rotation's *inverse* before solving "rotate the forearm rest direction
  onto it" -- using the raw world direction gives a plausible-looking but
  wrong pose (this failed on the first attempt and is exactly why the
  verification harness exists).
- `assets/rigid_arm_asset.usda`: new asset built by (1) referencing the
  original character file for materials and the untouched body, (2)
  authoring `over` opinions on the skin/tshirt/glove meshes that override
  just `faceVertexCounts`/`faceVertexIndices`/`primvars:st0:indices` to
  drop the right-arm faces (removes the original arm from the body without
  touching skinning, materials, or any other mesh -- the skeleton is never
  animated, so its live binding on the remaining meshes is a harmless
  no-op), and (3) defining new *non-skinned* Mesh prims for the extracted
  upperarm/forearm_hand face sets, points recentered to their own pivot,
  under a new `RightArmRig/ElbowPivot` Xform chain. Verified by computing
  each new prim's `ComputeLocalToWorldTransform` at rest (identity
  rotation) and confirming it reconstructs the ORIGINAL mesh's point
  positions to ~1e-7 (float32 rounding only) -- no sign/axis errors in the
  pivot math. Faces straddling the upperarm/forearm_hand/other boundary
  were dropped from every set (small seams expected at the shoulder/elbow,
  not yet judged on a real render).
- `isaacpjt/hand_intrusion_test_actor.py`: rewritten to drive this rig via
  `two_bone_ik` instead of the whole-body translate. Also caught and fixed
  a design bug during verification: a first draft held the torso fixed and
  only rotated the arm, but Chair_01 sits ~1.4 m from `TABLE_HAND_TARGET`

  character's two-bone arm only spans ~0.5 m -- geometrically unreachable

  pass #1 used) only far enough to leave
  `HAND_TEST_REACH_EXTENSION_RATIO` (default 0.85) of the arm's own reach
  to close, then bends the elbow for the remainder. Full pipeline (lean +
  shoulder rotate + elbow rotate) re-verified end to end against a
  synthetic hand marker: lands on `TABLE_HAND_TARGET` to ~1e-16 error, with
  a 115 deg shoulder angle / 65 deg elbow angle at full reach -- a real
  bend, not a fully-extended stiff arm. `HAND_TEST_RIG_MODE=legacy`
