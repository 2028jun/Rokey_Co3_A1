Human-readable log of every hardware pass run on the GPU machine for the
hand-safety intrusion test (see docs/VISION_TEST_GPU_PROMPT.md for the
full task). Append a new dated entry each pass -- see that doc's "Keep
GPU_RUN_LOG.txt updated" section for the template. Newest entry at the
bottom.

## Pass 1 -- 2026-07-22 (commit 6f8b848)

  Isaac Sim 5.1 + ROS 2 Humble hardware for the first time.

## Pass 2 -- 2026-07-22 (commits ddc1627, a84d3bf)

Tested:
- Raising table camera resolution to reduce YOLO upscale blur.
- A real per-joint arm reach via UsdSkel (rotate the forearm joint through
  a freshly-bound, rest-pose-seeded SkelAnimation), replacing the
  whole-body slide as the primary mechanism.
- Whether the per-joint approach actually renders on hardware, with an
  isolated pixel-diff repro (explicit simulation_app.update() ticks, a
  single deterministic rep.orchestrator.step() render -- no live-timing
  race possible).
- A fallback analytic whole-body-translate reach, with a long (20s),
  deliberately un-rushed hardware capture window.
- hand_safety's intrusion reading with the test person held at rest for
  120-180s (to isolate false positives from the reach mechanism itself).

Changed:
- mobile_manipulator_demo.py: connect_table_camera_ros2() RenderProduct
  640x480 -> 1280x960 (the ROI crop YOLO runs on was only ~289x262px at
  640x480, a ~4.4x upscale; at 1280x960 it's ~579x524px, ~2.2x upscale).
- hand_intrusion_test_actor.py: added then removed a per-joint UsdSkel
  reach (_setup_skeleton_reach() etc.) -- see "Observed" below for why.
- hand_intrusion_test_actor.py: replaced it with an analytic reach --
  compute the character's rest-pose right hand's world offset from its
  own root (hardcoded, measured once via GetBindTransformsAttr()), rotate
  by the placement yaw, and target the existing whole-body translate with
  that offset so the hand lands on TABLE_HAND_TARGET.

Observed:
- Per-joint UsdSkel rotation: UsdSkel.Cache/SkelQuery confirmed the
  joint's *computed* transform updated correctly, but the *rendered*
  image never showed the arm move -- proven, not a timing artifact.
  Writing through the Fabric-native usdrt.UsdSkel API instead of
  pxr.UsdSkel made no difference. Matches a documented NVIDIA caveat
  (omni.anim.graph.core changelog: "usdskel omnihydra does not handle
  both fabric + USD change well") -- late-bound SkelAnimation joint
  rotations don't appear to reach the Hydra skinning pipeline on this
  Isaac Sim build (5.1.0-rc.19), regardless of which USD API authors
  them. Per-joint rotation removed.
- Analytic whole-body reach: confirmed on hardware -- the character's
  hand lands squarely on the table during a reach. (Several earlier
  same-session captures that looked like it "wasn't rendering" were
  actually just mistimed, grabbed after a 2-4s reach window had already
  ended, given this test harness's own multi-step capture latency -- not
  a rendering bug.)
- New problem found while verifying acceptance: hand_safety's YOLO hand
  detector misdetects the robot's own RG2 gripper (permanently near the
  ROI) as two "hand" objects, so /hand_safety/roi_intrusion reads true
  continuously even with the test person held at rest the entire time.
  Pre-existing ROI/detector calibration issue, not introduced by this
  scaffold, but it currently masks any clean read of reach-correlated
  intrusion timing.

Still broken / follow-up (see docs/VISION_TEST_GPU_PROMPT.md's "Pass 3
tasks" section for the full writeup):
- Reach still looks unnatural: since this character's rest pose holds the
  arm up near shoulder height, bringing the hand down to table height
  means translating the whole body, so it visibly sinks/leans across the
  table rather than just extending an arm. Next idea to try: drive the
  arm via a PhysX articulation joint drive instead of UsdSkel animation
  (a different subsystem that may not hit the same late-bound-Fabric
  limitation) -- first needs checking whether this character asset even
  has a physics articulation on its skeleton, since many People
  background-crowd characters are pose-only with no physics joints.
- Gripper false-positive still blocks a clean acceptance check (roi
  reads true regardless of reach timing) -- needs the ROI polygon
  tightened to exclude the gripper's resting position and/or a raised
  YOLO confidence threshold against the gripper hardware.

## Pass 3 -- 2026-07-22 (commit 931d412)

Tested:
- Reach speed: HAND_TEST_TRAVEL_SECONDS 0.4 -> 0.8 (already applied blind
  before this pass) observed on hardware across many reach cycles.
- Whether F_Business_02's skeleton has a PhysX articulation, so the arm
  could be driven via a joint drive instead of UsdSkel animation.
- Repainting the RG2 gripper matte black to cut the hand-detector false
  positive, per a reviewer's suggestion.
- Root-caused the false-positive source properly: hid the wrist and fixed
  D455 camera assemblies (`UsdGeom.Imageable.MakeInvisible()`) and
  separately the whole kitchen -- the white object stayed visible through
  both, ruling out both suspects from pass 2's writeup. Forced
  `stage.Load()` and did a full unfiltered dump of every Mesh prim under
  `/World/ServingRobot` (with `Usd.TraverseInstanceProxies()`) to find it
  for real.
- Tightening `TABLE_ROI_NORMALIZED` in `hand_safety/hand_safety/
  roi_intrusion.py` to exclude the gripper's resting screen position,
  using exact bbox pixel data read from `/hand_detection/detections`
  (both with the test person forced to stay at rest for 120-180s, and
  during an active reach) instead of guessing.
- Final acceptance: `/hand_safety/roi_intrusion` over a 40s window with a
  short (3-4s) reach period, and separately over a 20s window with the
  person held at rest.

Changed:
- isaacpjt/mobile_manipulator_demo.py: `MOBILE_DEMO_MATTE_BLACK_GRIPPER`/
  `paint_gripper_matte_black()` were added, then fully removed after
  proving the approach doesn't work on this build (see Observed) --
  matches how per-joint UsdSkel rotation was handled in pass 2. No net
  change left in this file from the paint attempt.
- hand_safety/hand_safety/roi_intrusion.py: `TABLE_ROI_NORMALIZED`'s
  near-right corner moved from (0.731, 0.629) to (0.586, 0.629), pulling
  the ROI's right edge in far enough to clear the gripper's bbox
  (~x:786-831 px at 1280x960) while keeping the hand-test reach position
  (YOLO-observed at ~x:535-684 px during a reach) inside.

Observed:
- Reach speed at 0.8s travel reads as a reasonably natural pace across
  many observed cycles; no further change made.
- F_Business_02 has **zero** `UsdPhysics.ArticulationRootAPI` prims,
  `UsdPhysics.Joint`-derived prims, or `UsdPhysics.DriveAPI` prims
  anywhere in its referenced hierarchy -- confirmed dead end, exactly the
  "pose-only, no physics joints" case pass 2 flagged as a possibility.
  Physics joint drive is not viable for this character asset; would need
  a different, physics-rigged humanoid to try that path at all.
- Matte-black gripper repaint: root-caused the actual false-positive
  source properly this time (the RG2 gripper's own visual meshes --
  specifically gripper_body / *_inner_finger / *_outer_knuckle /
  *_inner_knuckle / quick_changer -- NOT the D455 camera housing as
  pass 2's writeup guessed). These meshes sit behind USD payloads with a
  generic "mesh" leaf name several levels down
  (".../gripper_body/node_STL_BINARY_/mesh"), which `stage.Traverse()`
  with the default predicate does not descend into, explaining why pass 2
  concluded they "don't exist." Binding a matte-black UsdPreviewSurface
  material was attempted three ways, each ruled out on hardware:
    1. Binding the leaf mesh directly: raises "authoring to an instance
       proxy is not allowed" (each STL part is instanced).
    2. De-instancing the ancestor first (`SetInstanceable(False)`) then
       binding: authoring succeeds, but the render is unaffected -- same
       "late edit doesn't reach Hydra" class of problem as pass 2's
       UsdSkel finding.
    3. Binding on the actual instance root instead of de-instancing
       anything (confirmed via `prim.IsInstance()`/`IsInstanceProxy()`
       walking the ancestor chain: the instance root is the "visuals"
       Xform two levels above "gripper_body", not "gripper_body" itself)
       -- this is the textbook-correct USD way to override per-instance
       material without touching the shared prototype, binding succeeds
       with no errors, and the render *still* doesn't change.
  All three were verified with matched before/after captures from the
  same running process, so this isn't a capture-timing artifact like the
  translate false-alarm in pass 2 -- material bindings on this specific
  already-populated/instanced/payload-loaded geometry just do not reach
  the renderer on this Isaac Sim build, regardless of API correctness.
  Abandoned; reverted all paint-related code.
- ROI tightening: fully resolved the false positive. With the person held
  at rest for 20s, `/hand_safety/roi_intrusion` read `False` for 256/256
  sampled messages (previously `True` continuously). With an active
  3-4s-period reach cycle running for 40s, `roi_intrusion` alternated
  cleanly between `False` (~25-37 samples, matching the wait/travel
  portion) and `True` (~15-51 samples, matching the 6s hold) in sync with
  each cycle -- the acceptance criterion from the original task prompt.

Still broken / follow-up:
- No natural per-joint arm reach exists for this character asset; the
  whole-body-slide/sink remains the only working mechanism. If a
  natural-looking reach is ever needed, it requires either a
  physics-rigged humanoid (for a real articulation joint drive) or the
  detached arm+hand prop fallback described in
  docs/VISION_TEST_GPU_PROMPT.md's pass-3 section (not yet tried).
- The broader "late edits to already-populated/instanced stage content
  don't reach Hydra on this Isaac Sim 5.1.0-rc.19 build" pattern has now
  been confirmed twice (UsdSkel joint rotation in pass 2, material
  binding in pass 3). Worth flagging to NVIDIA/Isaac Sim support if this
  keeps recurring -- it blocks a whole category of "tweak the already-
  loaded scene at runtime" approaches, not just this project's two
  attempts.
